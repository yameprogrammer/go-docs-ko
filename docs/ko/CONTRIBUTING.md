# Go에 기여하기

Go 프로젝트에 기여하고 싶으신 분들을 환영합니다! 이 가이드는 Go의 개발 프로세스와 기여 방법에 대해 설명합니다.

## 시작하기

Go에 기여하기 전에 다음 사항을 숙지하시기 바랍니다:

* **코드 스타일**: Go는 `gofmt`를 사용하여 일관된 코드 스타일을 유지합니다. 모든 제출 코드는 `gofmt`로 포맷팅되어야 합니다.
* **테스트**: 새로운 기능을 추가하거나 버그를 수정할 때는 반드시 관련 테스트 케이스를 포함해야 합니다.
* **리뷰 프로세스**: 모든 변경 사항은 코드 리뷰 과정을 거쳐야 하며, 메인테이너의 승인을 받아야 병합됩니다.

## 이슈 보고 및 버그 수정

버그를 발견했거나 기능 개선 제안이 있다면 다음 단계를 따르세요:

1. **기존 이슈 확인**: 이미 동일한 이슈가 보고되었는지 [GitHub Issues](https://github.com/golang/go/issues)에서 확인하세요.
2. **이슈 생성**: 새로운 이슈라면 명확한 제목, 재현 단계, 그리고 기대 결과와 실제 결과를 포함하여 이슈를 생성하세요.
3. **수정 및 제출**: 버그를 직접 수정하고 싶다면, 해당 이슈에 수정 의사를 밝힌 후 Pull Request(PR)를 제출하세요.

## 개발 환경 설정

Go 소스 코드를 빌드하고 테스트하려면 다음 단계가 필요합니다:

1. **소스 코드 내려받기**:
   ```bash
   git clone https://github.com/golang/go.git
   cd go/src
   ```
2. **빌드 수행**:
   ```bash
   ./make.bash
   ```
3. **환경 변수 설정**: `PATH`에 `go/bin` 경로를 추가하여 새로 빌드한 Go 툴체인을 사용하세요.

## Pull Request 가이드라인

PR을 제출할 때 다음 사항을 준수해 주세요:

| 항목 | 요구 사항 |
| :--- | :--- |
| **범위** | 하나의 PR은 하나의 논리적 변경 사항만 포함해야 합니다. |
| **테스트** | `go test ./...`를 통해 모든 테스트가 통과하는지 확인하세요. |
| **설명** | 왜 이 변경이 필요한지, 어떻게 해결했는지 상세히 기술하세요. |
| **포맷팅** | 모든 코드는 `gofmt`가 적용되어 있어야 합니다. |

## 커뮤니티 및 커뮤니케이션

Go 팀은 다양한 채널을 통해 소통합니다:

* **GitHub**: 코드 리뷰 및 이슈 추적.
* **Gopher Slack**: 실시간 논의 및 질문.
* **Mailing Lists**: 아키텍처 및 설계 논의.

기여해 주셔서 감사합니다! 여러분의 도움이 Go를 더 나은 언어로 만듭니다.

Go는 오픈 소스 프로젝트입니다.

수백 명의 기여자들이 함께 노력한 결과물입니다. 여러분의 도움에 감사드립니다!

## 이슈를 제기하기 전에

버그를 발견했는지 확실하지 않은 경우, 먼저 [golang-nuts 메일링 리스트](https://groups.google.com/forum/#!forum/golang-nuts)나 [다른 포럼](https://golang.org/help/)에 문의하시기 바랍니다. 확인 중인 동작이 버그나 이슈로 판명되면, 이슈 트래커에 쉽게 다시 제기할 수 있습니다.

## 이슈 제기하기

민감한 보안 관련 문제는 [security@golang.org](mailto:security@golang.org)로 보고해야 합니다.
자세한 내용은 [보안 정책](https://golang.org/security)을 참조하십시오.

이슈를 제기하는 권장 방법은 `go bug`를 실행하는 것입니다.
그렇지 않은 경우, 이슈를 제기할 때 다음 다섯 가지 질문에 반드시 답해 주세요:

1. 어떤 버전의 Go를 사용하고 계신가요 (`go version`)?
2. 어떤 운영체제와 프로세서 아키텍처를 사용하고 계신가요?
3. 어떤 작업을 수행하셨나요?
4. 예상하신 결과는 무엇인가요?
5. 실제로 어떤 결과가 나타났나요?

변경 제안에 대해서는 [Proposing Changes To Go](https://go.dev/s/proposal-process)를 참조하십시오.
