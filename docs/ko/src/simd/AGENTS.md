# SIMD 패키지 작업하기

이 패키지들이 무엇인지, 제너레이터들이 어떻게 서로 맞물리는지, 그리고 어떻게 실행하는지는 [archsimd/_gen/README.md](archsimd/_gen/README.md)에 설명되어 있습니다. 이 파일은 오직 컨텍스트 창(context window)을 낭비하지 않는 방법에 대해서만 다룹니다.

## 이 트리의 대부분은 부피상 생성된 것이며, 그중 일부는 거대합니다.

여기에서 생성된 파일들은 기계적으로 균일합니다. 수백에서 수천 개의 거의 동일한 연(stanza)으로 구성되어 있으며, 각 연은 하나의 문서 주석과 하나의 선언으로 이루어져 있습니다.

```go
// Add는 두 벡터의 해당 요소들을 더합니다.
//
// Asm: VPADDD, CPU Feature: AVX
func (x Int32x4) Add(y Int32x4) Int32x4
```

**두세 개의 스탠자(stanzas)만으로도 파일 전체의 내용을 파악할 수 있습니다.** 파일 전체를 처음부터 끝까지 읽는 것은 컨텍스트의 상당 부분을 소모하며, 샘플에서 배우지 못한 새로운 내용을 알려주지도 않습니다. 이는 API가 확장되어도 마찬가지입니다. 이러한 파일들은 더 다양해지는 것이 아니라 단순히 더 길어질 뿐입니다.

첫 번째 줄에 명시되어 있는 경우 파일이 생성됩니다:

```sh
head -1 <file> | grep 'Code generated'
```

기억하고 있는 큰 파일 목록에 의존하지 마십시오. 직접 측정하십시오:

```sh
find . -name '*.go' -size +50k -not -path '*/_gen/*' | xargs ls -lS
```

`archsimd/ops_*.go`, `internal/simdref/simdref.go`, `internal/bridge/decls_*.go` 및 `simd_test` 헬퍼들이 보통 해당 목록에 포함됩니다. 이를 전체 목록(inventory)이 아닌 시작점으로 간주하십시오.

## 샘플; 읽지 마세요

번역할 내용을 제공해 주세요. 요청하신 대로 Markdown 구조와 기술적 식별자를 유지하며 정확하게 한국어로 번역하겠습니다.

```sh
# 전체 문서 주석을 포함한 하나의 선언 형태
GOEXPERIMENT=simd go doc simd/archsimd.Int32x4.Add

# 어떤 리시버가 연산을 수행하는지 — 먼저 개수를 세고, 필요하면 목록을 출력하십시오
grep -c '^func ([^)]*) Add(' archsimd/ops_amd64.go
```

앵커링되지 않은 `grep Add`는 `AddSub`, `MulAdd`, `PairwiseAdd` 및 이를 언급하는 모든 `// Asm:` 라인과도 매칭됩니다. 일정한 간격의 스탠자(stanza)로 구성된 파일에서 `-A5`/`-B5` 옵션을 사용하면 파일의 대부분이 반환됩니다.

## 읽기 전에 도구 출력 크기 확인하기

`specls`는 확장된 spec API를 출력합니다. 출력 결과가 설명 대상 파일만큼 크기 때문에, `-f` (정규표현식)를 사용하여 범위를 좁히고 패턴에 앵커(anchor)를 사용하십시오.

```sh
go run ./cmd/specls -f '^Add$'   # 하나의 spec 함수
go run ./cmd/specls -f Add       # "Add"를 포함하는 모든 이름 — 훨씬 더 많음
go run ./cmd/specls              # 확장된 전체 API — 매우 방대함
```

diff에 대해서도 동일한 주의가 필요합니다. README에서는 `-diff`를 지속적으로 사용하라고 안내하며, 이는 옳은 방법입니다. 하지만 패밀리(family)를 재생성하면 수천 줄의 내용이 생성될 수 있습니다. 먼저 전체적인 형태를 파악한 다음, 중요한 부분을 읽으십시오.

```sh
git diff --stat
go run . -tools <tool> -diff | wc -l
```

## 생성된 파일은 수정하지 마세요

제너레이터 입력을 수정하고 다시 생성하십시오. 생성된 각 파일의 첫 번째 줄에는 해당 파일의 빌드에 사용된 입력 파일들의 이름이 명시되어 있습니다. 이를 통해 수정할 파일을 찾되, 해당 줄에 적힌 명령어를 직접 다시 실행하지 말고 `go generate`(README 참조)를 사용하여 다시 생성하십시오. 다시 생성된 출력물은 이를 유발한 변경 사항과 동일한 커밋에 함께 커밋하십시오.

## 만약 당신에게 단 하나의 스펙 전환 작업이 주어진다면

[archsimd/_gen/SPEC-TRANSITION.md](archsimd/_gen/SPEC-TRANSITION.md)가 현재 활성화된 계획입니다. 파트 2(근거; 작업들은 섹션 번호로 이를 인용함)와 파트 4에서 본인에게 할당된 작업을 읽으십시오. **파트 4를 처음부터 끝까지 읽지 마십시오** — 프로젝트의 모든 작업이 포함되어 있으며, 귀하에게는 그중 하나가 할당되었습니다.
