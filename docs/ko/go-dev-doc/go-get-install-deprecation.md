## 개요

Go 1.17부터 `go get`를 사용하여 실행 파일을 설치하는 것은 더 이상 권장되지 않습니다.
대신 `go install`을 사용할 수 있습니다.

Go 1.18에서 `go get`는 더 이상 패키지를 빌드하지 않고, `go.mod` 파일에 종속성을 추가, 업데이트 또는 제거하는 데만 사용됩니다. 구체적으로, `go get`는 항상 `-d` 플래그가 활성화된 것처럼 동작합니다.

## 대안은 무엇을 사용해야 할까요?

현재 모듈의 컨텍스트에서 실행 파일을 설치하려면 `go install`을 사용하고, 버전 접미사를 지정하지 않은 상태로 다음과 같이 실행합니다. 이는 현재 디렉터리 또는 상위 디렉터리에 있는 `go.mod` 파일에 있는 버전 요구 사항 및 기타 지침을 적용합니다.

```
go 설치 example.com/cmd
```

현재 모듈을 무시하고 실행 파일을 설치하려면 `go install`을 사용합니다.
`@v1.2.3` 또는 `@latest`와 같은 [버전 접미사](/ref/mod#version-queries)와 함께 사용하십시오. 버전 접미사와 함께 사용하면 `go install`은 현재 디렉토리 또는 상위 디렉토리에 있는 `go.mod` 파일을 읽거나 업데이트하지 않습니다.

```
# 특정 버전을 설치합니다.
go install example.com/cmd@v1.2.3

# 가장 최신 버전을 설치합니다.
go install example.com/cmd@latest
```

명확성을 위해, `go install` 명령을 버전 접미사와 함께 사용할 때,
모든 인수는 동일한 모듈 내의 동일한 버전의 `main` 패키지를 참조해야 합니다. 만약 해당 모듈에 `go.mod` 파일이 있다면, `replace` 또는 `exclude`와 같은 지시어가 포함되어 있어서, 이 모듈이 메인 모듈인 것처럼 해석되지 않도록 해야 합니다. 모듈의 `vendor` 디렉토리는 사용되지 않습니다.

자세한 내용은 [`go install`](/ref/mod#go-install)를 참조하세요.

## 이렇게 일어나는 이유

모듈이 도입된 이후, `go get` 명령어는 `go.mod` 파일의 종속성을 업데이트하고 명령어를 설치하는 데 사용되었습니다. 이러한 조합은 종종 혼란스럽고 불편합니다. 대부분의 경우, 개발자는 종속성을 업데이트하거나 명령어를 설치하고 싶지만, 동시에 두 작업을 수행하고 싶어하지 않습니다.

Go 1.16부터, `go install` 명령은 현재 디렉토리(존재하는 경우)의 `go.mod` 파일을 무시하고, 명령줄에서 지정된 버전을 사용하여 명령을 설치할 수 있습니다. `go install` 명령은 대부분의 경우에 사용해야 합니다.

`go get`의 빌드 및 설치 명령어 기능은 더 이상 사용되지 않습니다. 왜냐하면
이 기능은 `go install`과 중복되기 때문입니다. 이 기능을 제거하면 `go get`이 더 빨라집니다.
왜냐하면 기본적으로 패키지를 컴파일하거나 링크하지 않기 때문입니다.
`go get`은 현재 플랫폼에서 빌드할 수 없는 패키지를 업데이트할 때 오류를 보고하지 않습니다.

자세한 내용은 제40276호 제안서를 참조하세요.
