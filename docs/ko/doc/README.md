# 릴리스 노트

이 디렉토리의 `initial` 및 `next` 하위 디렉토리는 릴리스 노트(release notes)를 위한 것입니다.

## 개발자를 위해

릴리스 노트는 기존 파일을 수정하거나 새 파일을 생성하여 `next`에 추가해야 합니다. **CL에 `RELNOTE=yes` 주석을 추가하지 마십시오.** 대신, CL에 파일을 추가하거나 작성자에게 추가를 요청하십시오.

개발 주기 끝에, 파일들은 경로 이름순으로 정렬되어 연결됨으로써 병합됩니다. glob `"*stdlib/*minor"`와 일치하는 디렉터리의 파일들은 특별하게 처리됩니다. 이 파일들은 표준 라이브러리 패키지 경로에 해당하는 하위 디렉터리에 있어야 하며, 해당 패키지 경로에 대한 헤딩이 자동으로 생성됩니다.

이 리포지토리의 `api/next` 디렉토리에 있는 파일들은 `doc/next/*stdlib/*minor`에 대응하는 파일이 반드시 있어야 합니다.

파일들은 새로운 API가 포함된 패키지의 하위 디렉토리에 위치해야 하며, API 제안의 이슈 번호를 이름으로 지정해야 합니다. 예를 들어, `6-stdlib/99-minor` 디렉토리가 존재한다면, 다음과 같은 내용의 `api/next` 파일이 있을 때

pkg net/http, 함수 F #12345

`doc/next/6-stdlib/99-minor/net/http/12345.md`라는 이름의 대응하는 파일이 있어야 합니다.
해당 파일에는 최소한 완전한 문장이나 TODO가 포함되어야 하며, 가급적이면 해당 노트를 완성할 책임이 있는 담당자를 언급하는 것이 좋습니다.

CL이 승인된 제안(proposal)을 다루고 있다면, 릴리스 노트에 `/issue/NUMBER` 형식으로 해당 제안의 이슈 번호를 언급하세요. 텍스트 내의 이슈 링크는 다음과 같은 형식이 됩니다(아래 참조). 텍스트에 이슈를 언급하고 싶지 않다면, 다음과 같이 주석으로 추가하세요:

```
<!-- go.dev/issue/12345 -->
```

승인된 제안이 CL에는 언급되었지만 릴리스 노트에 언급되지 않은 경우, 자동화 도구에 의해 TODO로 표시됩니다. 이는 API를 추가하는 제안의 경우에도 마찬가지입니다.

번역할 Markdown 콘텐츠를 제공해 주세요. 요청하신 대로 Markdown 구조, 헤딩, 테이블, 링크, 리스트, 인라인 코드 및 코드 펜스를 유지하며, Go 패키지 이름, 식별자, URL, 명령어 또는 코드 스니펫은 번역하지 않고 정확하게 기술 번역을 수행하겠습니다.

[http.Request]                     # 심볼 문서; Go doc 문자열과 같이 자동 링크됨
	[Request]                          # 현재 문서화 중인 패키지 내 심볼을 위한 짧은 형식
	[net/http]                         # 패키지 링크
	[#12345](/issue/12345)             # GitHub 이슈
	[CL 6789](/cl/6789)                # Gerrit 변경 목록(changelists)

웹사이트의 로컬 인스턴스를 사용하여 병합된 형태의 `next` 콘텐츠를 미리 보려면 다음을 실행하십시오:

```
go run golang.org/x/website/cmd/golangorg@latest -goroot=..
```

그 다음 http://localhost:6060/doc/next 를 여십시오. 페이지를 새로고침하면 최신 수정 사항을 확인할 수 있습니다.

## 릴리스 팀을 위해

`golang.org/x/build/cmd/relnote`에 위치한 `relnote` 도구는 `doc/next`에 있는 파일들을 대상으로 작동합니다.

릴리스 주기가 완료될 때쯤, `relnote todo`를 실행하여 완료되지 않은 릴리스 노트 작업 목록을 확인하세요.

릴리스 노트를 준비하려면 `relnote generate`를 실행하세요.
그러면 `next`에 있는 `.md` 파일들이 하나의 파일로 병합됩니다.
해당 파일을 웹사이트 저장소의 `_content/doc` 디렉토리에 원자적으로(가능한 한 가깝게) 추가하고, 이 저장소의 `doc/next` 디렉토리를 삭제하세요.

다음 릴리스 개발 사이클을 시작하려면, `initial`의 내용을 `next`에 채우십시오. 리포지토리 루트에서 다음을 실행합니다:

> cd doc
    > cp -R initial/ next

그 다음 `next/1-intro.md`를 수정하여 다음 버전을 참조하도록 하십시오.
